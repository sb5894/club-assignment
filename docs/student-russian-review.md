# 학생 화면 한국어·러시아어 검토 기록

검토일: 2026-09-11

원자료: 사용자가 지정한 `2026 2학기 동아리 홍보자료 합본.pptx`의 전체 25개 슬라이드. 이미지 슬라이드를 직접 확인했다. 원본 발표자료는 저장소에 포함하지 않는다.

미디어ON은 이후 제공된 이미지 「미디어온(ON) 취재 쇼츠 연구소」를 우선 적용했다. 학교 이야기 취재, 짧은 영상 제작, 학교 채널 게시, 시청자 반응 관찰을 한 문장으로 요약했다. 한국어·러시아어 설명과 러시아어 이름을 함께 갱신했다.

## 적용 범위와 기존 코드 유지

- 학생 화면 `/`에만 한국어·러시아어 전환, 12개 동아리의 한 문장 설명, 러시아어 이름과 한글 이름 병기를 추가했다.
- 로그인, 접수 단계, 지망 순서, 저장·확인·재신청, 최종 배정, 오류 안내까지 번역했다.
- 언어 설정만 브라우저의 `student-language`에 보관한다. 입력 중인 코드·동아리 선택은 언어 전환으로 초기화되지 않는다.
- 인증·코드 발급·학생 명단·배정 로직·DB 스키마·마이그레이션·DB 연결 설정은 변경하지 않았다. 운영 DB 접속, 명단 재등록, 코드 재발급, 운영 배포를 수행하지 않았다.
- 브라우저 테스트는 가상 학생과 가짜 API 응답으로 진행했다. 기존 보안·저장소 테스트도 별도의 메모리 DB를 사용한다.

## 난이도 검토: 3회

동일 작성자가 서로 다른 기준으로 전체 번역을 세 번 검토했다. 러시아어를 읽는 초등 3~4학년이 이해하기 쉬운 표현을 목표로 한 정성 검토이며, 학생 대상 실측이나 외부 원어민 감수는 아니다.

| 회차 | 검토 기준 | 확인·수정 결과 |
| --- | --- | --- |
| 1 | 12개 설명의 어휘와 활동 이해 | 활동을 `рисуем`(그려요), `играем`(놀아요), `делаем`(만들어요) 등 구체적인 동사로 표현했다. 종이공예는 종이 만화영화, 디지털드로잉은 태블릿 그림으로 풀었다. 모든 동아리 설명은 한 문장이다. |
| 2 | 긴 문장·약어·학교 용어 | AI/ИИ와 3D 프린터를 설명하는 짧은 안내를 추가했다. 신청 변경 안내는 여러 짧은 문장으로 나눴다. 학년은 `Год обучения`, 반은 `Номер класса`, 번호는 `Номер в списке`로 구분했다. |
| 3 | 실제 화면에서 독립적으로 이해 가능한지 | 1·2·3지망은 `1-е/2-е/3-е место`와 원하는 순서에 대한 안내를 함께 표시한다. 버튼·오류·확인창까지 문장을 읽고 행동할 수 있는지 검토했다. 320·375·768px 화면에서도 이름과 설명이 잘리지 않도록 확인했다. |

## 기능 검증

- `npm test`: 60개 통과. 기존 발급 코드 호환성·세션·신청·배정 테스트 57개와 번역 누락·이름 병기·기존 동아리 데이터 보존 테스트 3개.
- `tsc --noEmit`: 통과.
- 변경한 TypeScript/TSX/MJS 파일의 `oxlint`: 통과.
- `npm run build`: 통과.
- Chrome 브라우저 검사: 18개 통과. 결과와 테스트 스크립트는 로컬 `work/student-browser-results.json`, `work/student-browser.mjs`에 있다.
- 브라우저에서 언어 저장, 입력 코드 유지, 12개 설명, 한글 병기, 선택 유지, 중복 선택 방지, 저장·확인·재신청, 취소, 단계별 화면, 오류 복구, 로그아웃, 교사 화면 한국어 유지, 저장 공간 차단 시 전환을 확인했다.
- 언어 전환으로 API 요청이 발생하지 않았고, 전체 학생 시나리오에 교사·코드 재발급 API 호출이 없었다. 브라우저 실행 예외는 0건이다.
- 발견한 320px 화면의 러시아어 제목 넘침을 수정하고 재검사했다.
- 전체 저장소 `npm run lint`는 기존 공통 UI·보조 훅의 오류 20건으로 실패한다. 해당 파일들은 이번 변경에 포함되지 않는다. 변경 파일 검사, 타입 검사, 빌드 및 위 기능 검사는 통과했다.

현재 결과는 로컬 변경이다. 운영 적용 시에는 현재 연결된 DB와 비밀 설정을 유지한 채 화면 변경을 배포해야 기존 발급 코드를 계속 사용할 수 있다.

## lint 오류의 실제 영향 추가 확인

lint를 다시 실행해 13개 파일의 20건을 확인하고, 학생 페이지·교사 페이지·공통 레이아웃·API·프록시에서 시작하는 로컬 import 연결을 추적했다. 연결된 28개 파일 중 오류가 있는 13개 파일은 하나도 포함되지 않았다. 따라서 이 20건은 현재 학생·교사 화면이나 신청·인증 API에서 실행되는 코드의 오류가 아니다.

분류는 HTML 요소·접근성 관련 14건, React 상태·ref 처리 3건, 차트 문자열 타입 3건이다. 사용하지 않는 UI 부품과 보조 훅에 남은 검사 오류로, 현재 코드에서 학생 코드 변경·신청 저장 실패로 이어지는 경로는 확인되지 않았다. 다만 저장소 전체 lint 검사는 계속 실패하므로 향후 해당 부품을 사용할 때에는 정리해야 한다. 추적 결과는 로컬 `work/lint-reachability.json`에 저장했다.
