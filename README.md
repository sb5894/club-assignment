# 학생 동아리 신청

학생용 `/`와 교사용 `/teacher`가 분리된 실제 운영 사이트입니다. 신청과 변경 이력은 Cloudflare D1에 저장하며 새로고침하거나 다른 기기에서 로그인해도 유지됩니다. 운영 데이터에는 가상학생을 넣지 않습니다.

## 사용 순서

1. `/teacher`에서 별도 관리 비밀번호로 로그인합니다.
2. `학년,반,번호,이름,성별` 열의 CSV 또는 엑셀 복사 내용을 등록합니다. 준비·접수 중 새 학생을 추가할 수 있고, 기존 학번을 덮어쓰지 않습니다.
3. 발급된 학생별 비밀 코드를 저장해 개별 전달합니다. 코드는 발급 시 한 번만 표시하며 분실하면 교사가 재발급합니다. 일반 명단 CSV에는 코드가 없습니다.
4. 정원과 고정 학생을 지정한 뒤 접수를 엽니다. 고정 학생을 먼저 배정하고 남은 정원은 모든 동아리에서 1→2→3지망 순으로 배정합니다.
5. 학생은 학년·반·번호와 코드로 로그인해 신청합니다. 다시 제출하면 현재 신청은 새 내용으로 대체되고 이전 내용과 제출 시각은 교사 전용 신청 이력에 남습니다.
6. 추첨 전 학생에게 `저장된 신청 다시 확인`과 `이 신청이 맞아요`를 안내합니다. 재신청하면 확인 완료 표시가 초기화됩니다. 접수 마감 후에도 조회·확인은 가능합니다.
7. 교사는 접수 마감 → 1지망 배정 → 결과 확인·조정 → 2지망 배정 → 결과 확인·조정 → 3지망 배정 → 최종 검토·확정 순으로 진행합니다. 한 번에 한 지망만 배정하며 새로고침해도 진행 단계가 유지됩니다. 이미 배정한 학생과 교사 조정은 유지하고 미배정 신청자만 다음 지망의 남은 정원에 배정합니다. 제출 후 미확인 학생도 동일하게 추첨에 참여합니다. 학생에게는 확정 후 자기 배정만 표시됩니다.

## 접수 마감 후 고정 명단 수정

- 신청을 다시 열지 않고 `고정 명단 수정`에서 고정 학생을 추가·이동·해제할 수 있습니다. 정원과 다른 동아리 정보는 변경할 수 없으며, 최종 확정 후에는 고정 명단도 잠깁니다.
- 저장 전 변경 대상과 배정 영향을 확인합니다. 배정 진행 중 추가·이동하면 해당 학생만 고정 동아리로 변경하고, 해제하면 미배정으로 돌아갑니다. 신청한 학생은 다음 지망부터 추첨에 참여하며 지난 지망은 다시 추첨하지 않습니다. 3지망까지 완료했다면 해제한 학생은 교사가 직접 배정합니다.
- 다른 학생의 배정과 기존 추첨 기록은 유지합니다. 기존 배정과 새 고정 명단을 합친 인원이 정원을 초과하면 저장을 차단합니다. 변경 이력은 운영 기록에 남습니다.
- 기존에 한꺼번에 배정한 결과는 3지망 완료로 읽습니다. 기존 결과를 변환하거나 재추첨하지 않으며, 데이터베이스 스키마 변경도 필요하지 않습니다.

## 접근과 기록

- 학생 코드 및 교사 비밀번호를 브라우저 코드에 저장하지 않습니다. 새 학생 코드는 무작위 영문 대문자·숫자 4자(I/O/0/1 제외)이며 기존 코드와 같은 명단 내 발급 코드의 중복을 검사해 다시 생성합니다. DB의 UNIQUE 제약도 중복 저장을 막습니다. DB에는 SHA-256 해시만, 교사 비밀번호는 PBKDF2-SHA256 검증값만 보관합니다. 기존 16자 코드는 재발급 전까지 유효합니다.
- HttpOnly/SameSite 세션 쿠키와 서버 인증으로 페이지·API를 보호합니다. 학생 조회·저장 대상은 로그인 세션에서 정하며 요청의 다른 학생 번호를 받지 않습니다.
- 교사 로그인은 반복 시도를 제한합니다. 학생 로그인은 학생별 제한과 학교 공유 IP를 고려한 제한을 함께 적용합니다.
- 재발급은 이전 코드와 기존 학생 세션을 무효화합니다. 이미 시작된 신청 요청도 저장 시점에 세션 유효성을 다시 확인합니다.
- 신청 버전 검사와 DB 트랜잭션으로 동시 제출의 덮어쓰기, 마감 후 제출, 낡은 교사 화면의 변경을 방지합니다.
- 신청 변경 이력은 DB 트리거로 기록하며 수정·삭제하지 않습니다. 교사 배정 및 설정 변경도 운영 기록으로 보관합니다.
- 서로 다른 기기의 현황은 `새로고침`으로 갱신합니다. 교사 비밀번호는 공용이므로 교사 개인별 신원 구분 기능은 없습니다.

## 로컬 실행과 검증

`pnpm install`

`.dev.vars.example`을 `.dev.vars`로 복사하고 `TEACHER_PASSWORD_HASH`에 `lib/server/auth.ts`의 `createPasswordHash()`로 생성한 검증값을 설정합니다. 실제 비밀번호와 `.dev.vars`는 커밋하지 않습니다. 배포 비밀값은 Sites에서 별도로 관리합니다.

`pnpm db:migrate:local`

`pnpm dev`

`pnpm test`

`pnpm build`

Windows 배포 빌드는 Node 22로 검증했습니다. `wrangler.jsonc`의 DB 식별자는 로컬 개발용이며 실제 DB는 Sites가 연결합니다. `.openai/hosting.json`에는 논리 바인딩 `DB`만 지정합니다. 새 스키마는 `pnpm db:generate` 후 SQL을 검토하고, 이미 배포된 마이그레이션은 변경하지 않습니다.

검증 범위: 250명 × 10회 배정, 지망별 진행·중간 조정·중복 실행 방지, 미확인 신청자 배정, 고정 명단 변경과 잔여 정원, 기존 배정 결과 호환, 학생별 정보 분리, 교사용 API 보호, 만료·재발급 세션, 동시 신청·마감, 재신청 이력 보존, 확인 상태 초기화. 자동 테스트 총 67개입니다. 별도 로컬 D1 테스트 DB에서 교사 로그인, 마감 후 고정 명단 변경·영향 확인, 지망별 배정·조정·새로고침, 모바일 화면, 최종 확정·잠금을 브라우저로 검증했습니다. 테스트 보고서는 `work/`에 생성되며 운영 배포에는 포함하지 않습니다.
