# 우리 동아리 데모

학생 신청, 1→2→3지망 동일 확률 추첨, 교사 조정과 CSV 내보내기를 체험하는 사이트입니다.
입력 양식의 동아리 이름 12개만 반영했으며 실제 학생 자료는 포함하지 않습니다.

- 가상 학생 236명, 5·6학년을 사용합니다.
- 또래상담 기본 최소 6명·최대 8명, 나머지 최소 15명·최대 25명입니다.
- 최소 인원은 배정 후 검토 기준이며 강제 이동하지 않습니다.
- 학년과 성별은 분포만 보여주고 추첨 가중치로 사용하지 않습니다.
- 같은 입력과 추첨 번호는 같은 결과를 재현합니다. 학생과 동아리 입력 순서에 영향을 받지 않습니다.
- 상태는 React 메모리에만 있습니다. 새로고침하면 초기화되며 기기 간 공유되지 않습니다.
- 신청과 교사용 화면 전환은 체험 기능이며 사용자 인증이나 권한 분리가 아닙니다.
- CSV는 엑셀에서 열 수 있으며 JSON 기록에는 입력, 추첨 대상·당첨자, 교사 조정 사유를 담습니다.
- 동아리 상세 화면에서 배정 명단과 1·2·3지망 신청자를 탭으로 확인합니다. 모든 지망을 표시하며 해당 신청 지망 또는 실제 당첨 지망을 굵게 표시합니다.
- 정원·배정 설정에서 일부 고정 후 지망별 추첨을 선택하고 학생을 지정합니다. 고정 학생만 먼저 배정하고 추첨에서 제외합니다. 해당 동아리도 남은 정원에 대해 1→2→3지망 배정에 참여하며, 정원 초과 시 추첨합니다.
- 고정 명단은 중복과 정원 초과를 검사하며 고정 학생만 배정 후 교사 조정으로 변경할 수 없습니다. 고정되지 않은 학생은 해당 동아리로 이동하거나 나올 수 있으며 정원을 준수합니다. 고정 명단은 배정 전에 설정하거나 데모 초기화 후 다시 지정합니다.

실제 운영에는 중앙 데이터 저장, 교사 로그인, 학생별 신청 코드, 중복 수정 정책, 신청 마감과 백업이 필요합니다.

## 검증

`node --experimental-strip-types --test lib/allocation.test.mjs lib/allocation.simulation.test.mjs`

250명씩 10회(총 2,500명) 다른 신청 분포·정원·고정 명단으로 배정합니다. 매회 후보와 당첨자, 정원, 중복, 지망 순서, 미배정 집계, 고정 명단을 확인하고 같은 시드 및 입력 순서 변경으로 재현성을 검증합니다. 결과는 `work/allocation-validation.json`에 저장합니다. 지망이 모두 마감된 학생은 미배정으로 남는 것이 정상입니다.

`pnpm build`

선택적 WebMCP 도구 2개를 기능 감지 후 등록합니다. 자동 검증은 배정 로직, 타입 검사, 코드 검사와 배포 빌드 범위이며 실제 브라우저 클릭 및 WebMCP 컨텍스트 검증은 포함하지 않습니다.
